# 首版核心验收清单

下表为首版真实业务验收预期。2026-11-10已执行账号/资料及需求草稿的真实PostgreSQL、SMTP和Chrome联调，已覆盖部分见文末记录；未实现流程不提前标通过。参见[运行说明](../../README.md)。用需求方A/B、老师T、运营O等不同合成账号分别操作；P0角色切换不算跨账号权限验证。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| MVP-01 | 注册、邮箱验证、登录 | 主动成年声明；邮件打开不自动验证，确认后再登录；未验证账号不能进入业务写入 |
| MVP-02 | 忘记密码、退出和换账号 | 正常找回不泄露账号存在性；旧/过期链接不能复用；重置撤销旧会话；换账号不显示前一账号私有内容 |
| MVP-03 | 首次选身份、再次登录 | 一个账号一种身份；重复点击/两端竞争不会绑定两种；普通账号不能取得运营权限 |
| MVP-04 | 本人资料与发布门槛 | 只有展示名也可发布，无展示名提示补齐；B不能改A资料，联系方式不因此公开 |
| MVP-05 | 草稿三步保存、再打开 | 下一步成功保存才跳转；第二步不清掉第一步；失败留输入；离开未保存页选择有效 |
| MVP-06 | 需求字段及边界 | 按首版字段表验证文字/金额/小时/频率/时段/日期及声明；非法输入不静默舍入或修正 |
| MVP-07 | 提交、重复点击与冲突 | 只产生一次提交；他人不可提交；旧版本不覆盖；超时不误报失败或再次盲建需求 |
| MVP-08 | 待审与公开 | 待审本人只读、匿名不可见；无待审直接编辑/撤回；保存草稿不等于已提交 |
| MVP-09 | 审核通过/驳回 | 运营不能审本人；驳回理由必填；按固定提交审核；两人并发只能一个合法结果 |
| MVP-10 | 驳回修改重提 | 本人修订后重新审核；保留上次内容与理由，不能覆盖旧提交 |
| MVP-11 | 到期与公开字段 | 北京时间边界正确；待审过期不批准，公开过期立即不可见，不等清理任务；禁止新增及重发意向，已有待回应仍可接受/拒绝/撤回，已有互选继续管理授权；公开返回无联系方式/邮箱/精确地址/隐藏截止日/私有声明/审核内部信息 |
| MVP-12 | 老师资料与发现 | 展示名、服务类别、服务方式、介绍必填；含线下方式时街道必填，仅线上可不填；类别/方式/街道支持多选；介绍/时间长度及报价双端约束按主规格；报价和时间说明选填，空值分别展示“面议”/“时间可协商”；保存不自动公开，补齐后本人主动公开，无资料人工审核；公开后保存须仍满足必填项，失败不改线上内容；停止公开立即退出发现并停止新增撮合，已有关系与快照保留；公开资料仅已登录需求方查看，不泄露私密联系方式，不把自述当核验事实 |
| MVP-13 | 老师投递、需求方邀请 | 仅本人合法身份发起；老师资料须已主动公开才可投递/被邀请，未补齐/未公开时提示完善并公开；邀请须选本人有效公开需求；返回明确等待对方状态，不直接互选 |
| MVP-14 | 回应、重复与撤回 | 仅待回应方可接受/拒绝，发起方只能撤回本人待回应意向；同一需求/老师仅一条进行中关系；重复/反向/并发发起进入已有进度，不自动互选；被拒绝方不能对同一提交版本重发，拒绝方可主动再发；撤回后满足新增条件可再发；新一轮不继承旧回应或授权；接受与撤回冲突按最新状态展示 |
| MVP-15 | 联系方式授权/撤回 | 未互选/单方同意时不返回对方值；双方同意后仅展示选中字段；任一撤回立即停止后续访问；已分享值变更触发重确认 |
| MVP-16 | 完整走通及页面可用 | 需求方发布→运营审核→老师投递/需求方邀请→回应互选→双方授权→撤回；老师不进入需求方本人操作；未勾选声明不能注册/提交；取消撤回回到原授权状态，不凭跳转展示联系方式；停止公开不新增撮合但已有关系继续；手机/桌面主要任务可操作，错误可见且能恢复 |

实际报告记录所用代码/接口/迁移版本、场景ID、步骤、响应及必要数据库断言、浏览器证据与未验证项。只在相应行为真实验证后标通过；旧OpenAPI校验、Figma截图和[P0报告](p0-report.md)不能替代本清单。
