## 交付顺序

| 步骤 | 做什么 | 完成条件 |
| --- | --- | --- |
| 1. 核心规则和字段 | 沿用已确认账号/需求字段，补老师资料、投递邀请及回应规则 | 规则直接维护主规格；常规设计自主补齐，特别重要或确实不确定的业务结果才集中询问 |
| 2. 核心页面 | 在原Figma中串通需求方、老师、运营主路径；补真实表单控件、必填/可选、确认及必要失败提示 | 用户从页面知道填什么、看什么、点什么以及下一步；不要求补齐所有延期画面 |
| 3. 必要接口和数据 | 页面稳定后定义请求/返回、权限、状态条件与主要错误，确定所需数据实体 | 每个核心动作都有对应接口；旧接口只按需复用，不整套照搬 |
| 4. 分段开发联调 | 账号/基本资料 → 草稿 → 提交审核公开 → 投递邀请互选 → 联系方式 | 每段一起完成前端、后端、数据库并用不同账号走通，再推进下一段 |
| 5. 首版验收 | 走通撮合闭环，检查关键失败/越权及手机桌面主要操作 | 交付可运行版本及[核心验收](../acceptance/mvp-cases.md)的实际结果，后续改进另列 |

当前核心规则、原Figma核心表单/路径、只读预览及必要接口设计已整理。2026-11-08用户明确授权第一段真实开发，要求先写代码、以环境配置占位，数据库/邮件由用户后续提供再联调；已进入步骤4的账号/基本资料代码实现，尚无真实数据库、发信或跨账号业务通过证据。

## 接下来如何推进

1. 从原Figma索引按需求方、老师、运营各自入口查看当前核心设计；不再逐条询问普通字段/按钮，也不恢复延期路线。
2. [必要接口与数据](../contracts/README.md)已按当前页面列明请求/返回、权限、状态及主要错误；实际实现相应业务段时再转成机器契约并联调，不照搬旧0.3.1。
3. 第一段账号/基本资料按本次授权先完成前后端、迁移和配置代码，待用户提供数据库/邮件后一起验证；第一段实际走通后再依次推进草稿、审核公开、投递互选和联系方式。
4. [核心验收](../acceptance/mvp-cases.md)仍全部待真实执行；当前结构/截图/静态验证只证明设计稿与预览范围，不记业务通过。

保留基本对象权限、密码保护、需求未经审核不公开、老师资料未经本人主动公开不展示、联系方式定向授权、重复提交与版本冲突处理。复杂通用设施和技术参数由开发按当前动作选择，不要求用户先理解一整套技术平台。

## 工作边界

- 复用Vue工程和原Figma文件，不重设计全项目、不重建Figma。
- 已确认事项直接沿用，不重复询问；建议与决定明确分开。
- 先完成一段可运行的业务，再推进下一段；当前第一段为账号/基本资料，发布审核浏览在后续增量，不等于整个首版完成。
- 对外开放所需的实际主体/类别、必要说明与数据处理事项单列落实；合成设计与开发无需等待所有未来功能定稿。
- 进度按用户能完成什么任务报告，设计、静态检查与真实业务测试分开。

## 2026-11-08 第一段代码开发

用户已明确授权真实开发，同时限定本轮先写代码及配置占位，不要求安装数据库、Docker、邮件或部署；真实环境由用户后续提供。本轮未初始化Git，未发现适用AGENTS.md；不恢复延期功能，不改动原Figma。

本次代码覆盖的用户任务：

- 注册时主动确认成年，申请验证邮件；明确点击确认后才能验证，缺少原浏览器上下文须核对注册密码，验证成功后另行登录。
- 使用已验证账号登录、退出，正常申请重置密码；明确重置使全部旧会话失效。邮件未配置时不会跳过验证，也不把已受理写成已送达。
- 首次确认需求方或老师一种身份，重复选择同身份不新增，竞争选择另一身份返回冲突；没有运营自选入口。
- 需求方保存展示名；老师保存不完整资料，完整后预览并主动公开，公开后合法修改、停止公开及重新公开。
- 保存失败保留输入；版本冲突先读取并核对最新资料；浏览器其他标签页更换账号时，旧资料写入会被账号前置条件拒绝。

代码位置：frontend/src/AccountApp.vue为当前前端入口，backend为Spring Boot服务，V1迁移包含账号、本人/老师资料、一次性邮件凭据摘要、会话摘要、必要限流及公开操作幂等回执。私密联系方式维护和授权留第五段；老师发现列表及需求流程未实现。当前不是完整首版。

环境：Node.js v24.11.0、npm 11.6.1、JDK 25.0.4.1可用。Maven不在PATH，但进一步发现用户缓存内有可执行Maven 3.10.0，本轮使用它在项目.tools/maven-repository下载依赖并编译；项目另提供可复用的mvnw.ps1入口。未安装系统服务。数据库和SMTP连接均未配置；占位字段和启动/测试方式维护在[项目入口](../../README.md)、[后端配置示例](../../backend/.env.example)及[前端代理示例](../../frontend/.env.example)。
