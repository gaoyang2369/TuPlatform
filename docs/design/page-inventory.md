# 首版核心页面清单

任务入口可以合并为同一页面的步骤/状态，不按历史画面数量建路由。规则及字段以[首版规格](../mvp-spec.md)为准，原节点由[figma-state.json](figma-state.json)定位。

| 使用者 | 核心任务 | 既有编号 | 当前需做 |
| --- | --- | --- | --- |
| 通用账号 | 注册/邮箱验证、登录、忘记密码/重置 | G-01相关状态 | 复核表单、主动声明和主要失败提示；保留正常邮箱找回 |
| 账号本人 | 首次选一种身份、本人基本资料、退出 | G-02、P-08/T-04相关 | 移出恢复/换绑/完整归档入口；补最小资料页面 |
| 需求方 | 发现老师、老师详情、选需求邀请 | P-01/P-02 | 已登录需求方查看主动公开的老师资料；展示本人自述，不显示已认证；报价空值显示“面议”、时间空值显示“时间可协商”；邀请须选本人有效公开需求 |
| 需求方 | 我的需求、基本信息、时间预算、预览 | P-03/P-04a/P-04b/P-05 | 核对已确认字段、控件、单位和保存/提交区别 |
| 需求方 | 待审、驳回反馈、修订、到期、候选 | P-06/P-07 | 待审只读；暂不做公开编辑/暂停/关闭 |
| 老师 | 本人资料、投递/邀请列表 | T-04/T-03 | 按主规格标记必填/选填；类别、方式、街道支持多选，线下服务须选区域；报价区间与时间文字选填；区分保存与主动“公开资料”，无资料人工审核；未公开仅本人可见 |
| 老师 | 公开需求列表、详情、投递 | T-01/T-02 | 仅已公开资料的老师可投递；缺必填项或未公开时引导补齐并主动公开；明确有效公开需求、投递确认与已有进度入口 |
| 双方 | 收到投递/邀请、回应、互选进度 | S-01相关状态 | 已按主规格补确认、接受/拒绝、撤回及重发；需求到期不终结已有关系；老师和需求方分别进入自己的进度与授权路径 |
| 双方 | 逐项授权、等待对方、有效展示、撤回 | S-03相关状态 | 复核本人视角、内容变更重确认与停止展示 |
| 运营 | 审核列表、固定提交详情、通过/驳回 | A-01/A-02 | 最小审核界面及非本人审核约束 |

先串通“需求方发布→运营审核→老师投递→需求方接受→双方授权”，再核对“需求方邀请→老师回应”的对称路径。不同账号分别操作，设计中的多角色起点不代表正式产品可切角色。

人工恢复、双人复核、换绑、完整纠错/归档、资料证件核验、完整通知/聊天、争议工作台及S-04起预约/结果/合作/评价均不在当前页面交付内。原画面保留在同一Figma文件，已标注延期并切断从核心页面进入的导航；本地预览将延期样例折叠到历史区。

## 本轮控件与状态

以下为已写入原Figma和本地样例源的设计，不是已实现或真实业务通过证据。新增画面表示同一路由的状态/确认步骤，不要求逐画面建立路由。

| 任务 | 控件及主要状态 |
| --- | --- |
| 老师填写并公开资料 | 文本输入、多行介绍、类别/方式/街道复选框、上下限两个报价输入；仅保存与主动公开分开，公开前预览，补齐错误定位；公开后明确“保存并更新公开资料”，停止公开二次确认 |
| 需求三步发布 | 类别/阶段/街道/方式下拉，预算双输入，小时与次数输入，星期和起止时间，添加/删除时段，日期、多行备注；未勾选声明时禁止提交，另有已勾选状态；手动保存及下一步先保存 |
| 投递与邀请 | 发出前核对对象与当时资料，发出后等待；未公开老师资料、没有本人有效需求各有就近引导；同一需求/老师的重复与反向发起进入已有进度，不自动互选 |
| 回应与互选 | 接受与拒绝均有确认；发起方仅在待回应时可撤回；本人拒绝和被对方拒绝的可用动作不同；到期已有意向仍可回应，已有互选继续管理授权 |
| 联系方式 | 逐字段复选、本人分享预览、等待对方、双方有效授权、撤回和已分享值变更状态；老师独立进入本人授权；取消撤回返回打开前的进度，不跳到双方已授权样例 |
| 本人资料与导航 | 需求方只必填展示名，联系方式单独私密维护；老师与需求方使用各自账号入口；匿名仅浏览公开需求并引导登录；运营侧栏仅保留需求审核 |

共用失败处理：输入错误就地提示并保留内容；保存失败不改变已保存/公开内容；结果未知先确认同一次结果，不盲建；版本冲突重读最新状态，不覆盖他人回应；无数据给出浏览/发布/完善资料入口。需要登录时回到登录，服务端仍须独立检查对象权限。

Figma可表达控件、选择状态和固定跳转；文本输入、增删时段、实际保存、跨账号同步及手机软键盘行为须在真实实现阶段验证。本地HTML中的表单为只读/禁用合成样例。
